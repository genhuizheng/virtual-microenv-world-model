## 1. What the project is

A single-cell **world model** predicting treatment response:

```
pretreatment cell expression  ->  post-treatment cell expression
```

Training data is MOSCOT-paired pre/post cells from the same patient. The model
is two-stage:

- **Stage 1 (representation)** — encode expression into a latent, decode back.
  Trained once, then **frozen**.
- **Stage 2 (transition / world model)** — learn the pre→post move *in that
  frozen latent*. Levels 1-6; Level 6 is CellFlow-style conditional flow
  matching, the intended final model.

At inference: `encode(x_pre)` → transition → `decode(z_pred)` = predicted
post-treatment expression, in the same gene space. That is what makes
gene/pathway/patient-level analysis possible downstream.

**Current focus: Stage 1 only.** Stage 2 is parked until the representation is
settled, because Stage 1 sets Stage 2's ceiling (§7).

## 4. Why the earlier results were invalid

Every 50k/500k screening run used `--representation-type legacy_mlp` with
`--expression-loss-weight 0` and `--source-recon-loss-weight 0` (both default
to 0, never set). Therefore:

1. **The decoder never received a gradient** — it stayed randomly initialized.
   `y_pred` from those checkpoints is noise.
2. **Each architecture trained its own private encoder** with no reconstruction
   constraint. Every level shaped a latent that made its own transition task
   easy, so the rankings partly measured which model invented a more convenient
   coordinate system.

The two-stage design (train representation, freeze, then screen transitions) is
the fix, and is why Stage 1 had to be settled first.

## 5. Data problems found and fixed

### 5.1 Technology/platform metadata was lost — recovered

`Code/preprocessing/batch_processing.py` writes `technology`/`platform` to
`adata.uns["metadata"]` (lines 379-380), not `obs`; the pairing step builds
shards from `obs`. The source `Sample_info/*/Sample info.txt` tables are **gone**
(266 empty directories), but the values survive in `uns["metadata"]` of the 568
per-patient/dataset h5ads.

| technology | n_pairs | pct |
|---|---:|---:|
| 10X Genomics | 44,722 | 89.44 |
| 10x Genomics | 3,869 | 7.74 |
| BD Rhapsody | 909 | 1.82 |
| Microwell-seq | 225 | 0.45 |
| Seq-Well | 170 | 0.34 |
| MARS-seq | 105 | 0.21 |

`10X` vs `10x` is the same platform — must be case-normalized or it becomes two
batch categories for a difference that does not exist.

**Decision: drop non-10x (2.82%).** Done.

### 5.2 `dataset_id` is biologically confounded — do not use as batch key

`dataset_id` is the **scCT-DB dataset ID** (266). Per scCT-DB's methods those
are partitioned by therapeutic regimen, dosage, cancer subtype, sampling time,
**drug-response grouping**, technology, and source study. Most of those are
biological.

Conditioning on it would remove treatment regimen and response status — the
signal being modelled. Chreode explicitly avoids the analogous mistake by
keeping developmental timepoint out of its batch covariate.

**Decision: use `source_study`** — the accession embedded in `patient_id`
(`E-MTAB-12733-Pt1` → `E-MTAB-12733`). 65 studies, one lab/protocol each.
Derived at load time by regex; no shard rebuild.

### 5.3 The zero-filled gene panel

A dataset measures 10,972–40,581 of 46,143 genes (median 25,259), so **~45% of
a typical cell's vector is padding** — and the padding pattern is a per-study
fingerprint *inside the values*, unreachable by any batch covariate.

**Consequence A — Gaussian variance collapse.** With `--gene-likelihood normal`
on the full panel: 11,020 genes (23.9%) at `exp(px_r) < 1e-3`, min 2.7e-08;
train loss −1.87e+5, val 3.04e+10. Collapsed genes' mean detection rate 0.00003
vs 0.05422 (**1,800× lower**); 78.6% of never-detected genes collapsed vs 4.7%
of detected ones. An always-zero column lets a Gaussian fit μ=0, σ→0 for
unbounded density. NB/ZINB is structurally immune.

**Consequence B — parameter bloat.** 119.1M parameters against ~75k training
cells (1,588/cell). Depth is nearly free (1→3 layers changes <1%); width
doubles cost.

| panel | genes | mask density min/med/max | overall |
|---|---:|---|---:|
| full union | 46,143 | 0.24 / 0.55 / 0.88 | 0.56 |
| ≥50% of datasets | 26,015 | 0.42 / 0.93 / 1.00 | 0.87 |
| **≥90% of datasets** | **15,163** | 0.71 / **1.00** / 1.00 | **0.99** |
| intersection | 9,712 | 1.00 | 1.00 |

**Decision: ≥90% panel (15,163 genes).** At 99% density explicit masking would
act on ~1% of entries. Intersection rejected — 9,712 is 62% below the median
dataset's own panel. (15,163 is close to Chreode's 16,520 shared orthologs,
arrived at independently.)

**Result:** variance collapse eliminated (0 collapsed genes); ~119M → ~39M
parameters.

### 5.4 Evaluation was scoring against padding

Reconstruction was initially scored over all genes including structural zeros.
On a test fixture this **inverted the ranking**: an unmasked control scored
Pearson 0.56 mask-blind, −0.0006 mask-aware — its apparent skill was predicting
always-zero genes.

**Fix:** `--gene-mask-npz` restricts scoring to measured genes for every config.
Also: **per-cell Pearson is the cross-config metric**; MSE is only comparable
within a unit group (log1p vs bin indices are different quantities).

## 6. Screen results — 25 configs, fold 0, 50k

### Which axis matters

| axis | Pearson effect | verdict |
|---|---|---|
| **scGPT binning (bin_51)** | 0.69 → 0.40–0.47 | **harmful** |
| **model family** (masked VAE vs scVI) | 0.69 → 0.54–0.63 | scVI better |
| **batch correction** | ~0 | mix 13.3→8.6, role 1.38→1.32 |
| log1p vs raw counts | 0.678 → 0.691 | +2%, negligible |
| zinb / nb / poisson | 0.6776 / 0.6816 / 0.6824 | **flat** |
| panel 15k vs 26k | 0.6776 / 0.6785 | **identical** |

### Negative results (all useful)

- **Zero-inflation and overdispersion earn nothing** — Poisson ≥ NB ≥ ZINB flat
  within 0.5%.
- **Panel size inert** 15k vs 26k on every metric.
- **Masking made no difference** — `m50_bat_log1p_mask` (0.6066/3.12×/1.06×) vs
  `m50_bat_log1p_full` (0.6084/3.03×/1.06×), from an architecture-matched
  control built to detect exactly this. **Hold loosely:** the whole masked-VAE
  family underperformed (role ≈ 1.05–1.19, near-erased), so the comparison
  happened inside a weaker model. More likely the implementation (untuned KL,
  plain MLP, 50 epochs from scratch) than a verdict on masking.
- **Binning inside scVI failed** — bin indices have no library size but scVI's
  decoder still applies library scaling. Testing scGPT's claim properly needs a
  model built for it.

### The batch-correction trade

| config | Pearson | mix | role |
|---|---|---|---|
| `p90_nob_zinb` (no batch) | 0.6836 | 13.24× | **1.38×** |
| `p90_bat_zinb` (source_study) | 0.6776 | **8.52×** | 1.32× |
| `p90_bat_log1p` | 0.6909 | 7.43× | 1.24× |

Mixing and role move together, monotonically. Reconstruction barely moves
(0.153–0.168), so this is about *what the latent encodes*, not quality.

**Metric meanings:** `mix` = fraction of k=30 nearest latent neighbours from the
same source study, ÷ chance. Lower is better; 1.0 = fully mixed. `role` = same
statistic for pre/post treatment label. **Higher** is better; 1.0 = signal
erased. Judge them together — either is trivially won by degrading the other.

## 7. The open problem: generalising to new datasets

**Goal:** given pretreatment data from a *new* dataset, predict post-treatment
without rebuilding the pipeline.

`source_study` cannot do this — a new study is an unseen category with no
embedding. Batch correction buys correction across *known* studies, not
transfer to unknown ones.

Retraining Stage 1 per new dataset works but changes the latent, so Stage 2's
weights must be retrained too. Every new dataset then rebuilds the whole
pipeline — a procedure to re-run rather than a model to apply — and needs the
new dataset to be large enough to train a VAE.

**`technology` was tested as a closed-set alternative and failed:**

| batch key | mix | generalises? |
|---|---|---|
| none | 13.27× | yes |
| **technology** | **13.45×** | yes, but **corrects nothing** |
| source_study | 8.64× | **no** |

Informative rather than merely negative: the batch structure is **study-level,
not platform-level**. With 97% of cells on 10x, a technology key has nothing to
separate. Study identity is inherently an **open set**, so no closed-category
batch key can substitute.

### Remaining options

1. **Accept `nob`** — encodes anything, no correction, best role (1.38×).
   Defensible: MOSCOT pairs are within-patient, so the transition model never
   compares cells across studies.
2. **Adversarial batch-invariant latent** (not built) — study classifier with
   gradient reversal; labels used only in training, none needed at inference.
   The only approach giving correction *and* generalisation. Risk: stronger
   constraint than conditional correction, may cost more role signal; if role
   → 1.0 it has erased the task.
3. **scPoli learnable batch embeddings** (not built) — fit a new embedding per
   new study against a frozen model. Cheaper than retraining, still a
   per-dataset fitting step.

**This is a decision about how the model will be used, not something the
metrics settle.**

## 10. Operational gotchas hit this session

1. **Unpushed commits.** Twice, TACC ran stale code because a local commit was
   never pushed. Check `git log origin/main..HEAD` before submitting.
2. **Bare conda env name fails on compute nodes.** Use the full path.
3. **`sbatch` breaks `$0`-based path resolution** — SLURM copies the script to a
   spool dir. Use `SLURM_SUBMIT_DIR`.
4. **`git checkout <file>` discards uncommitted work.** Cost one rewrite.
5. **`scikit-misc` fails to build on aarch64** (nvfortran lacks
   `-fortran_std=legacy`). Fix: `conda install -c conda-forge scikit-misc`,
   then `pip install --no-deps scvi-tools`.
6. **h5py backed reads need increasing row indices** for dense matrices; sparse
   shards avoid it.
7. **Login nodes have no GPU** — `--device cuda` there will fail.
