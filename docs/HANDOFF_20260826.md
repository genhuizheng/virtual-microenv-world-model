## 1. What the project is

A single-cell **world model** predicting treatment response:

```
pretreatment cell expression  ->  post-treatment cell expression
```

Training data is MOSCOT-paired pre/post cells from the same patient. The model
is two-stage:

- **Stage 1 (representation)** — encode expression into a latent, decode back.
  Trained once, then **frozen**.
- **Stage 2 (transition / world model)** — learn the pre→post move *in that
  frozen latent*. Levels 1-6; Level 6 is CellFlow-style conditional flow
  matching, the intended final model.

At inference: `encode(x_pre)` → transition → `decode(z_pred)` = predicted
post-treatment expression, in the same gene space. That is what makes
gene/pathway/patient-level analysis possible downstream.

**Stage 1 is settled** (`p90_nob_nb`, §7.1) and Stage 2 has run once at 50k
(§8.6). Current work is the 500k pipeline (§8.8).

## 4. Why the earlier results were invalid

Every 50k/500k screening run used `--representation-type legacy_mlp` with
`--expression-loss-weight 0` and `--source-recon-loss-weight 0` (both default
to 0, never set). Therefore:

1. **The decoder never received a gradient** — it stayed randomly initialized.
   `y_pred` from those checkpoints is noise.
2. **Each architecture trained its own private encoder** with no reconstruction
   constraint. Every level shaped a latent that made its own transition task
   easy, so the rankings partly measured which model invented a more convenient
   coordinate system.

The two-stage design (train representation, freeze, then screen transitions) is
the fix, and is why Stage 1 had to be settled first.

## 5. Data problems found and fixed

### 5.1 Technology/platform metadata was lost — recovered

`Code/preprocessing/batch_processing.py` writes `technology`/`platform` to
`adata.uns["metadata"]` (lines 379-380), not `obs`; the pairing step builds
shards from `obs`. The source `Sample_info/*/Sample info.txt` tables are **gone**
(266 empty directories), but the values survive in `uns["metadata"]` of the 568
per-patient/dataset h5ads.

| technology | n_pairs | pct |
|---|---:|---:|
| 10X Genomics | 44,722 | 89.44 |
| 10x Genomics | 3,869 | 7.74 |
| BD Rhapsody | 909 | 1.82 |
| Microwell-seq | 225 | 0.45 |
| Seq-Well | 170 | 0.34 |
| MARS-seq | 105 | 0.21 |

`10X` vs `10x` is the same platform — must be case-normalized or it becomes two
batch categories for a difference that does not exist.

**Decision: drop non-10x (2.82%).** Done.

### 5.2 `dataset_id` is biologically confounded — do not use as batch key

`dataset_id` is the **scCT-DB dataset ID** (266). Per scCT-DB's methods those
are partitioned by therapeutic regimen, dosage, cancer subtype, sampling time,
**drug-response grouping**, technology, and source study. Most of those are
biological.

Conditioning on it would remove treatment regimen and response status — the
signal being modelled. Chreode explicitly avoids the analogous mistake by
keeping developmental timepoint out of its batch covariate.

**Decision: use `source_study`** — the accession embedded in `patient_id`
(`E-MTAB-12733-Pt1` → `E-MTAB-12733`). 65 studies, one lab/protocol each.
Derived at load time by regex; no shard rebuild.

### 5.3 The zero-filled gene panel

A dataset measures 10,972–40,581 of 46,143 genes (median 25,259), so **~45% of
a typical cell's vector is padding** — and the padding pattern is a per-study
fingerprint *inside the values*, unreachable by any batch covariate.

**Consequence A — Gaussian variance collapse.** With `--gene-likelihood normal`
on the full panel: 11,020 genes (23.9%) at `exp(px_r) < 1e-3`, min 2.7e-08;
train loss −1.87e+5, val 3.04e+10. Collapsed genes' mean detection rate 0.00003
vs 0.05422 (**1,800× lower**); 78.6% of never-detected genes collapsed vs 4.7%
of detected ones. An always-zero column lets a Gaussian fit μ=0, σ→0 for
unbounded density. NB/ZINB is structurally immune.

**Consequence B — parameter bloat.** 119.1M parameters against ~75k training
cells (1,588/cell). Depth is nearly free (1→3 layers changes <1%); width
doubles cost.

| panel | genes | mask density min/med/max | overall |
|---|---:|---|---:|
| full union | 46,143 | 0.24 / 0.55 / 0.88 | 0.56 |
| ≥50% of datasets | 26,015 | 0.42 / 0.93 / 1.00 | 0.87 |
| **≥90% of datasets** | **15,163** | 0.71 / **1.00** / 1.00 | **0.99** |
| intersection | 9,712 | 1.00 | 1.00 |

**Decision: ≥90% panel (15,163 genes).** At 99% density explicit masking would
act on ~1% of entries. Intersection rejected — 9,712 is 62% below the median
dataset's own panel. (15,163 is close to Chreode's 16,520 shared orthologs,
arrived at independently.)

**Result:** variance collapse eliminated (0 collapsed genes); ~119M → ~39M
parameters.

### 5.4 Evaluation was scoring against padding

Reconstruction was initially scored over all genes including structural zeros.
On a test fixture this **inverted the ranking**: an unmasked control scored
Pearson 0.56 mask-blind, −0.0006 mask-aware — its apparent skill was predicting
always-zero genes.

**Fix:** `--gene-mask-npz` restricts scoring to measured genes for every config.
Also: **per-cell Pearson is the cross-config metric**; MSE is only comparable
within a unit group (log1p vs bin indices are different quantities).

## 6. Screen results — 25 configs, fold 0, 50k

### Which axis matters

| axis | Pearson effect | verdict |
|---|---|---|
| **scGPT binning (bin_51)** | 0.69 → 0.40–0.47 | **harmful** |
| **model family** (masked VAE vs scVI) | 0.69 → 0.54–0.63 | scVI better |
| **batch correction** | ~0 | mix 13.3→8.6, role 1.38→1.32 |
| log1p vs raw counts | 0.678 → 0.691 | +2%, negligible |
| zinb / nb / poisson | 0.6776 / 0.6816 / 0.6824 | **flat** |
| panel 15k vs 26k | 0.6776 / 0.6785 | **identical** |

### Negative results (all useful)

- **Zero-inflation and overdispersion earn nothing** — Poisson ≥ NB ≥ ZINB flat
  within 0.5%.
- **Panel size inert** 15k vs 26k on every metric.
- **Masking made no difference** — `m50_bat_log1p_mask` (0.6066/3.12×/1.06×) vs
  `m50_bat_log1p_full` (0.6084/3.03×/1.06×), from an architecture-matched
  control built to detect exactly this. **Hold loosely:** the whole masked-VAE
  family underperformed (role ≈ 1.05–1.19, near-erased), so the comparison
  happened inside a weaker model. More likely the implementation (untuned KL,
  plain MLP, 50 epochs from scratch) than a verdict on masking.
- **Binning inside scVI failed** — bin indices have no library size but scVI's
  decoder still applies library scaling. Testing scGPT's claim properly needs a
  model built for it.

### The batch-correction trade

| config | Pearson | mix | role |
|---|---|---|---|
| `p90_nob_zinb` (no batch) | 0.6836 | 13.24× | **1.38×** |
| `p90_bat_zinb` (source_study) | 0.6776 | **8.52×** | 1.32× |
| `p90_bat_log1p` | 0.6909 | 7.43× | 1.24× |

Mixing and role move together, monotonically. Reconstruction barely moves
(0.153–0.168), so this is about *what the latent encodes*, not quality.

**Metric meanings:** `mix` = fraction of k=30 nearest latent neighbours from the
same source study, ÷ chance. Lower is better; 1.0 = fully mixed. `role` = same
statistic for pre/post treatment label. **Higher** is better; 1.0 = signal
erased. Judge them together — either is trivially won by degrading the other.

## 7. The open problem: generalising to new datasets

**Goal:** given pretreatment data from a *new* dataset, predict post-treatment
without rebuilding the pipeline.

`source_study` cannot do this — a new study is an unseen category with no
embedding. Batch correction buys correction across *known* studies, not
transfer to unknown ones.

Retraining Stage 1 per new dataset works but changes the latent, so Stage 2's
weights must be retrained too. Every new dataset then rebuilds the whole
pipeline — a procedure to re-run rather than a model to apply — and needs the
new dataset to be large enough to train a VAE.

**`technology` was tested as a closed-set alternative and failed:**

| batch key | mix | generalises? |
|---|---|---|
| none | 13.27× | yes |
| **technology** | **13.45×** | yes, but **corrects nothing** |
| source_study | 8.64× | **no** |

Informative rather than merely negative: the batch structure is **study-level,
not platform-level**. With 97% of cells on 10x, a technology key has nothing to
separate. Study identity is inherently an **open set**, so no closed-category
batch key can substitute.

### Remaining options

1. **Accept `nob`** — encodes anything, no correction, best role (1.38×).
   Defensible: MOSCOT pairs are within-patient, so the transition model never
   compares cells across studies.
2. **Adversarial batch-invariant latent** (not built) — study classifier with
   gradient reversal; labels used only in training, none needed at inference.
   The only approach giving correction *and* generalisation. Risk: stronger
   constraint than conditional correction, may cost more role signal; if role
   → 1.0 it has erased the task.
3. **scPoli learnable batch embeddings** (not built) — fit a new embedding per
   new study against a frozen model. Cheaper than retraining, still a
   per-dataset fitting step.

### 7.1 Resolution — `p90_nob_nb` chosen

**5-fold CV** over the three promoted configs (fold-0 numbers were pessimistic
throughout; every config gained ~0.02 Pearson and ~0.06 role when averaged):

| config | Pearson | mix | role |
|---|---|---|---|
| `p90_bat_log1p` | **0.7074** | **9.00×** | 1.31× |
| `p90_bat_nb` | 0.7005 | 10.37× | 1.39× |
| `p90_nob_nb` | 0.7010 | 14.25× | **1.44×** |

The batch/no-batch gap is real, not fold noise: 14.25× → 10.37× mixing for a
role cost of 1.44 → 1.39 and **zero** reconstruction cost.

**But correction only takes 14.25× → 10.37×, against a chance rate of 1.0.**
Both are enormously far from mixed. The trade is therefore not "correction vs
generalisation" but "a partial fix that costs new-dataset transfer, versus no
fix that doesn't" — a worse bargain than fold 0 suggested.

**Adversarial variant was built and tested** (`--adversarial-weight` in
`train_stage1_masked_vae.py`; gradient-reversed study classifier, labels used
only in training, label-free inference verified). Weight sweep on real data:

| config | Pearson | mix | role |
|---|---|---|---|
| scVI `p90_nob_nb` | **0.7010** | 14.25× | **1.44×** |
| Gaussian VAE, adv w=0 | 0.6111 | 2.66× | **1.05×** |
| adv w=0.1 | 0.5532 | 6.42× | 1.10× |
| adv w=0.5 | 0.5965 | 6.49× | 1.07× |
| adv w=2.0 | 0.6028 | **2.04×** | **1.01×** |

**The control at w=0 already has role 1.05×** — the treatment signal was gone
before any adversarial pressure. The adversary did not destroy it; the base
Gaussian VAE never had it. Every masked-VAE config this session landed at role
1.01-1.19.

This also exposes a trap in the mixing metric: the Gaussian VAE's 2.66× looks
like far better correction than scVI's 14.25×, but it is **information loss
wearing the costume of batch correction** — near-chance on study *and*
near-chance on treatment. Judged on mixing alone the degenerate model wins.
This is precisely why the role metric exists alongside it.

Untested hypothesis for the collapse: `masked_vae.py`'s `mlp()` begins with
`nn.LayerNorm(n_genes)`, normalizing each cell across genes on input that
`log1p_10k` already library-normalized. That double normalization would strip
per-cell magnitude — plausibly the axis treatment moves cells along.

**DECISION: `p90_nob_nb`.** Highest role of anything tested (1.44×),
Pearson tied with the best (0.7010), and it encodes any new dataset with no
batch label. Its 14.25× residual study clustering is real and should be
reported honestly — but every alternative that reduced it did so by discarding
the signal the world model needs.

The adversarial path is not refuted, only untested: it needs a base model with
scVI-level signal retention, and fixing the Gaussian VAE is a separate project.

## 8.6 Stage-2 50k screen -- results and diagnosis

All 13 tasks completed. Ranked on `val_loss_pair`, 11/13 beat the level-0
identity floor (0.432421) by 13-16%. But the result pattern, not the ordering,
is what matters:

| finding | evidence |
|---|---|
| two configs were **the same model** | byte-identical val curves to 16 decimals |
| everything peaked at epoch 0-1 of 50 | 8 of 13 configs |
| the winners span only 1.7pp | 13.1%-14.8% for 10 of 11 |

### The duplicates were a real design error

`level3_gated_dit` and `level5_tokenized` produced identical curves and matching
parameter counts (45,172,084); so did `level2_dit` and `level5_rectified`
(45,172,083). Two causes:

- `DiTTokenBackbone.forward` computes `norm(x).mean(dim=1)` -- the same
  expression as `DiTBackbone.forward`, over the same submodules in the same
  construction order. The token path exists only for variants that call
  `forward_tokens` (cross-attention, hierarchical). So `tokenized_dit` == level 3.
- **`delta` is the constant 1.0.** `--time-delta-col` defaults to `None`, so
  `sample_paired_h5ad_dataloader.py` fills `default_time_delta=1.0` for every
  pair. `rectified_dit`'s `step * velocity` with `step = clamp(1.0)` is then
  exactly level 2's `z + residual`.

**Consequence of constant delta, beyond the tie:** `FourierTimeEmbedding(delta)`
returns the same vector for every cell, so AdaLN conditioning carries zero
information in *every* DiT config, and `TimeGate` collapses to a single
learnable scalar `1 - exp(-1/tau)`. The elapsed-time axis -- what conceptually
separates levels 3, 4 and 6 -- was inert for the whole screen. Check for a real
timepoint column before trusting any time-conditioned result.

### Two independent failures, not one

Train/val curves separate them:

| | level2_dit | level4_waddington |
|---|---|---|
| train | 0.5535 -> 0.3507 (monotone) | 0.6956 -> 0.3810 (monotone) |
| val | 0.3751 @ep1, then rises to 0.3943 | 0.3626 @ep8, then turns |

**Overfitting** -- level 2's val rises from epoch 2 while train keeps falling.
**Regression to the mean** -- `metric_mmd` worsens (0.0322 -> 0.0344) during
epochs 0-8 when level 4's val `loss_pair` is genuinely *improving* on held-out
patients. That is not overfitting; it is the objective. MOSCOT supplies a
probabilistic coupling, not a ground-truth cell-to-cell correspondence, so the
per-cell target carries irreducible pairing noise and minimising MSE against it
shrinks the predicted distribution.

Level 4 generalised **8x longer than level 2 on identical data**. Its potential
+ skew-symmetric-rotation + stochastic decomposition acts as a structural
regulariser. That is the one genuinely architectural finding in the screen, and
it is unaffected by the delta bug (level 4 touches `delta` only through the
constant gate and constant embedding).

## 8.7 The fold-assignment bug

`compute_group_to_fold` assigned folds by **position in a shuffled roster**
(`shuffle(groups)` then `i % num_folds`), making every assignment depend on
which other patients were in `data_dir`. Measured:

```
50k patients: 406 | 500k patients: 408
shared: 406 | same fold: 67 (16.5%)
LEAKING (500k fold-0 val, but were in 50k Stage-1 train): 68
```

Two extra patients moved 83.5% of assignments. Reusing the 50k Stage-1 encoder
at 500k would have put **68 of ~82 fold-0 validation patients (83%) into the
encoder's training set** -- leakage straight into the model-selection number.

**Fixed** -- `_stable_fold()` hashes `f"{seed}:{group}"` with blake2b, so fold
membership is a property of the patient and is identical at 50k, 500k or 1M.
Verified 100% stable across rosters, 0 leaking, fold sizes 73-88 (vs 81
expected -- hashing trades exact round-robin balance for roster independence).
blake2b rather than builtin `hash()`: `PYTHONHASHSEED` randomises str hashing
per process, which would desynchronise trainer and evaluator.

**Every checkpoint trained before this fix sits on a different split and must
not be reused across data directories.** The 50k Stage-2 screen is internally
valid (one directory, one seed) but its numbers cannot be pooled with post-fix
runs.

Related fix: checkpoint selection used `val_loss_pair` for every mode except
`cellflow`, which silently broke `--loss-mode chreode` -- it would optimise
MMD/W2 but select the epoch that best fit the per-cell target. Now always
`val_loss_total`. No behaviour change for `pair_mse` (there `loss == loss_pair`
whenever the aux weights are 0, their defaults).

## 8.8 Stage 2 at 500k -- the current plan

| file | purpose |
|---|---|
| `tacc_commands/TACC_stage1_500k.sh` | Refit `p90_nob_nb` at 500k, single job |
| `stage2_screen500k_configs.tsv` | 21 configs: 10 architectures x 2 objectives + CellFlow native |
| `tacc_commands/TACC_stage2_screen500k_array.sh` | `-a 0-20%4` |

**Stage 1 is refit, not re-screened.** The 25-config screen answered *which
configuration*, and its margins came from effects independent of data volume
(binning 0.69 -> 0.41, masked VAE degenerate, likelihood ladder flat within
0.5%, 15k ~= 26k genes). Only the winner's weights need refitting -- required
regardless, because of section 8.7.

**The objective replaces data volume as the second axis.** 500k has 408
patients against 50k's 406: it is ~10x more cells from the *same* patients, not
more patient diversity. It should let the model learn cell-state-conditional
dynamics (pairs per patient ~123 -> ~1,230) instead of per-patient mean shifts,
but it will not close the cross-patient gap on its own.

Dropped from the grid: `tokenized_dit` and `rectified_dit` (provably identical
to levels 3 and 2, section 8.6).

Epochs 10, not 50 -- at 500k an epoch is ~1,560 steps vs ~157, so this is
~15,600 steps against the 50k screen's 7,850. More optimisation, fewer epochs;
passes over the data are what drive overfitting.

**Reading the two floors.** Level 0 anchors both arms and they mean different
things: for `pair_mse` it is the loss of doing nothing; for `chreode` it is the
MMD/W2 between pre and post as they stand -- a much harder floor, since an
identity map already has substantial population overlap. **A config that beats
the floor on `pair_mse` but not on `chreode` has learned a mean shift.**
`rank_stage2_screen.py` ranks each arm on its own objective against its own
floor, then cross-compares on `metric_mmd` at the selected checkpoint (not the
per-epoch minimum, which would credit an epoch the selection rule would never
have chosen).

## 10. Operational gotchas hit this session

1. **Unpushed commits.** Twice, TACC ran stale code because a local commit was
   never pushed. Check `git log origin/main..HEAD` before submitting.
2. **Bare conda env name fails on compute nodes.** Use the full path.
3. **`sbatch` breaks `$0`-based path resolution** — SLURM copies the script to a
   spool dir. Use `SLURM_SUBMIT_DIR`.
4. **`git checkout <file>` discards uncommitted work.** Cost one rewrite.
5. **`scikit-misc` fails to build on aarch64** (nvfortran lacks
   `-fortran_std=legacy`). Fix: `conda install -c conda-forge scikit-misc`,
   then `pip install --no-deps scvi-tools`.
6. **h5py backed reads need increasing row indices** for dense matrices; sparse
   shards avoid it.
7. **Login nodes have no GPU** — `--device cuda` there will fail.

**Fold assignment was leaking across data directories (section 8.7) -- fixed.**
Any checkpoint trained before the fix must not be reused across scales.

**Next: the 500k pipeline (section 8.8).** Refit Stage-1 `p90_nob_nb` at 500k,
then a 21-config Stage-2 screen crossing 10 architectures with `pair_mse` vs
`chreode`. The objective, not data volume, is the second axis -- 500k turned out
to be the same 406 patients.

**Known gaps:**
- `spatial_validation/predict_pre_to_post.py` calls `model.encode(xb)` /
  `model.decode(z_pred)` without `batch_categories` (lines 105-111). Works for
  the old representations; will refuse a batch-conditioned scVI checkpoint.
  **Must be updated before any `p90_bat_*` model can serve predictions.**
- `source_study` folds drop ~14% of validation cells (2,860/19,950) because 6
  studies land entirely in the held-out fold. Inherent to a study-level batch
  key with patient-level folds; recurs every fold. Revisit before 500k.
- The masked VAE loads its split densely (~10GB at 26k × 97k). Fine on GH200,
  not viable for 1M without streaming. The scVI path has no such limit.
- Stage 2 has not been rerun at all with a valid representation. Everything in
  `docs/initial_screening.md` and `docs/500k_model_selection.md` is superseded.

**What Stage 2 screening will mean now:** with a fixed frozen representation, a
level/variant comparison finally measures dynamics rather than each model's
private coordinate choice. The `role` metric is also the guard — a
representation whose role ratio approaches 1.0 has erased the pre/post
distinction, and no transition model can recover it. **Stage 1 sets Stage 2's
ceiling.**
